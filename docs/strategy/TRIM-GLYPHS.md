# Trim glyphs — the notion→cartridge→parameter inventory

**What this is.** A read-only inventory that answers one question for every
Fashion Cabinet `notion`: *which Yantra4D cartridge embodies it as a solid, and
which of that cartridge's manifest parameters would a **2D glyph** of it scale
by?* It is the supply list for the flats-gallery v2 tile set and for the
lexicon's drawing vocabulary.

**What this is not.** No glyphs are drawn here, and no shape language is
proposed. Every number below is counted from the bridge data; nothing is
invented, estimated or rounded up. Where the data is thin the row says so.

## Provenance

| Input | Source |
| :-- | :-- |
| Notions | `notion` object in each `projects/*/project.json` of the Fashion Cabinet commons (one per garment) |
| Bridge links | `notion.hardware_ref` → `{platform, project_slug, linked, params_map}` |
| Cross-check | FC `docs/interfaces/bridge-index.json` (`fc_bridge_index_v1`, generated by `scripts/qa/generate_bridge_index.py` against the vendored Y4D hardware snapshot at upstream commit `80892074`) |
| Parameters | `parameters[].id` / `type` / `min` / `max` / `default` in each Yantra4D `projects/<slug>/project.json` |

Counts as observed:

- **516** FC garment manifests scanned; **311** carry a `notion`.
- **9** notion kinds — the nine below; no others appear.
- **303** notions carry a `hardware_ref` (all `platform: yantra4d`); **8** carry
  none, and all eight are explicitly closure-free garments (see *Custom*).
- **299** hardware refs are `linked: true`; **4** are `linked: false`.
- **89** distinct target slugs; **88** exist as in-tree Yantra4D cartridges.
  The one exception is `hammer-loop`, a co-create target that has no cartridge
  yet — FC's own `unlinked_claims` records it.
- **967** `params_map` entries; **965** resolve to a real parameter `id` in the
  target cartridge's manifest. The 2 that do not are `hammer-loop`'s `span`
  and `strap_w`, which have no manifest to resolve against.

A `params_map` key *is* the Yantra4D parameter; the value is the garment-side
expression that drives it. So the key set of a kind is exactly the dimensional
vocabulary FC already speaks to that solid — which makes it the right vocabulary
for a glyph, rather than a fresh one invented at drawing time.

## Kind by kind

Each table row is one Yantra4D cartridge, with the number of FC notions that
resolve to it, the number of distinct subtype phrases those notions use, and the
cartridge parameters their `params_map`s actually drive, ordered by how many
notions drive each.

### button — 53 notions

| Cartridge | Notions | Subtypes | Parameters driven |
| :-- | --: | --: | :-- |
| `sew-through-button` | 36 | 34 | `button_ligne`, `hole_count`, `hole_spacing`, `hole_dia`, `thickness`, `dish_depth`, `card_count` |
| `shank-button-solid` | 11 | 10 | `diameter_mm`, `thickness`, `rim`, `holes`, `hole_dia` |
| `jeans-button` | 4 | 1 | `head_dia`, `head_h`, `socket_dia`, `socket_h`, `tack_dia`, `tack_h` |
| `magnetic-button-cover` | 2 | 1 | `button_dia`, `button_t`, `hole_dia`, `sew_holes` |

The subtype phrases are placement prose ("henley placket button column",
"two-column double-breasted sew-through buttons", "mary-jane instep-strap
button") rather than a controlled vocabulary, but the cartridge they resolve to
partitions them cleanly: 36 sew-through, 11 shank, 4 tack-set jeans button
(all one phrase, "tack-set jeans button on the waistband extension"), 2
magnetic button-cover.

A button glyph is a circle plus a hole pattern. Its two governing inputs are
already in the data: **diameter** — as `button_ligne` (12–60 L, integer, the
trade unit) for sew-through, as `diameter_mm` (6–60 mm) for shank — and
**hole count**, which is `hole_count` (2 or 4, step 2) or the `holes` select
(2 or 4). `hole_spacing` (2–12 mm) sets the hole circle; `thickness` and
`dish_depth`/`rim` are edge-profile depth and carry no 2D signal. `card_count`
(2–12) is a mode parameter for the button-card, not a button.

### zipper — 22 notions

| Cartridge | Notions | Subtypes | Parameters driven |
| :-- | --: | --: | :-- |
| `zipper` | 15 | 10 | `zip_length`, `tape_width`, `chain_size`, `tape_thick`, `gap` |
| `invisible-zipper` | 6 | 6 | `zip_length`, `tape_width`, `coil_dia`, `tape_thick` |
| `zipper-loop-aid` | 1 | 1 | `ring_id`, `ring_w`, `part_t`, `tab_t`, `tab_w` |

Observed subtype vocabulary is the tightest of any kind: 12 phrases contain
"separating" (including "separating-2way" and "two-way separating centre-front
zipper"), 6 are invisible or concealed, 2 are closed-end, plus "leheṅgā side
closure" and "three-sided U-path zip".

A zipper glyph scales along one axis and quantises across the other.
**`zip_length`** (20–1200 mm on `zipper`, 60–600 on `invisible-zipper`, step 5)
is the run; **`tape_width`** (4–20 mm) is the drawn band width; and
**`chain_size`** is the tooth gauge as a four-value select — `#3 (light /
dresses)`, `#5 (jackets)`, `#8 (bags / heavy)`, `#10 (outerwear)` — which is
the tooth-pitch input a glyph would repeat its tooth mark on. On the invisible
variant the equivalent is `coil_dia` (1.5–4 mm), the coil bead. `tape_thick`
and `gap` are print-fit, not drawing inputs.

### buckle — 21 notions

| Cartridge | Notions | Subtypes | Parameters driven |
| :-- | --: | --: | :-- |
| `strap-buckle` | 6 | 5 | `webbing`, `web_t`, `wall`, `snap_clear` |
| `side-release-buckle` | 4 | 4 | `webbing_w`, `webbing_t`, `body_t`, `wall_t` |
| `d-ring` | 3 | 3 | `webbing`, `bow_depth`, `wire_t`, `wire_h` |
| `overall-buckle` | 3 | 3 | `strap_w`, `frame_h`, `wire_t`, `button_dia`, `depth` |
| `belt-buckle` | 2 | 2 | `strap_width`, `bar_dia`, `prong_d` |
| `cam-buckle` | 1 | 1 | `webbing_w`, `webbing_t` |
| `ladder-lock` | 1 | 1 | `webbing_w`, `webbing_t`, `frame_t` |
| `tri-glide-slider` | 1 | 1 | `webbing_w`, `webbing_t` |

Eight cartridges for 21 notions — the most fragmented kind, because "buckle"
covers webbing hardware (side-release, ladder-lock, tri-glide, cam), ring
adjusters (D-ring), and prong frames (belt, overall).

Every one of them is scaled by **the strap it passes**, under four spellings of
the same quantity: `webbing` (select `20mm` / `25mm` / `38mm` on
`strap-buckle`, slider 10–60 mm on `d-ring`), `webbing_w` (15–50 mm),
`strap_w` (15–60 mm), `strap_width` (15–50 mm). A glyph's width is that value;
its aspect then comes from the second parameter — `frame_h` (20–90 mm) on
`overall-buckle`, `bow_depth` (8–60 mm) on `d-ring`, `body_t` (5–14 mm) on
`side-release-buckle`. `wire_t` / `wire_h` / `frame_t` / `wall` are the drawn
stroke weight of the frame; `bar_dia` and `prong_d` size the centre bar and
prong marks. `snap_clear` is print-fit.

### snap — 13 notions

| Cartridge | Notions | Subtypes | Parameters driven |
| :-- | --: | --: | :-- |
| `sew-on-snap` | 8 | 8 | `snap_dia`, `sew_holes`, `stud_dia`, `disc_t`, `hole_dia`, `engage_clear` |
| `snap-electrode-carrier` | 3 | 3 | `disc_dia`, `disc_t`, `sew_holes`, `hole_dia` |
| `snap-fit` | 2 | 2 | `bore_dia`, `beam_width`, `wall` |

Three cartridges split three real uses: the sewn garment snap (8), the e-textile
electrode carrier that reuses the snap footprint (3), and the printed
cantilever `snap-fit` used as a storm-flap fastener (2).

A snap glyph is two concentric circles and a ring of sew holes:
**`snap_dia`** (7–30 mm) or **`disc_dia`** is the outer circle,
**`stud_dia`** (2.5–8 mm) the inner, and **`sew_holes`** (3–8, integer) is the
count of rim marks with `hole_dia` (1–2.5 mm) their size. `disc_t` is
thickness; `engage_clear` is print-fit. `snap-fit` is a different geometry
altogether (`bore_dia`, `beam_width`) and should not share a glyph.

### rivet — 6 notions

| Cartridge | Notions | Subtypes | Parameters driven |
| :-- | --: | --: | :-- |
| `rivet` | 4 | 4 | `cap_h`, `bore_dia`, `burr_dia`, `cap_dia`, `post_dia`, `post_h` |
| `bag-feet` | 1 | 1 | `foot_dia`, `foot_h`, `washer_dia` |
| `chicago-screw` | 1 | 1 | `head_dia`, `post_dia`, `stack_t` |

The smallest kind. Two of the four `rivet` notions are "load-path rivet at …"
placements and two are "tubular rivet …"; the other two cartridges take one
notion each ("wallet corner binding screw", "weekender base feet").

Face-on, a rivet glyph is a filled disc with an optional washer ring:
**`cap_dia`** (5–20 mm) / `head_dia` / `foot_dia` is the disc,
**`burr_dia`** (4–20 mm) / `washer_dia` the ring, and `post_dia` (2–12 mm) the
shank mark. `cap_h`, `post_h`, `foot_h` and `stack_t` are depth-only —
notable because rivets are the kind whose `params_map`s lean hardest on
height (`cap_h` is driven by all 4), which a 2D glyph cannot show.

### eyelet — 8 notions

| Cartridge | Notions | Subtypes | Parameters driven |
| :-- | --: | --: | :-- |
| `garment-eyelet` | 8 | 8 | `inner_dia`, `barrel_h`, `flange_dia`, `wall`, `washer_t` |

The only kind with a single cartridge and therefore a single glyph. Four of the
eight subtypes are lacing eyelets, three are tie/throat eyelets, one is
explicitly "garment eyelet + washer".

The glyph is an annulus: **`inner_dia`** (3–12 mm, the finished hole) inside
**`flange_dia`** (8–24 mm). `wall` (0.8–2.5 mm) is the barrel stroke,
`washer_t` distinguishes the washer variant. `barrel_h` (1.5–8 mm) is the
fabric stack it passes and is invisible face-on — but it is driven by 7 of the
8 notions, so a flats gallery that wants to distinguish a light-shirt eyelet
from a boot eyelet needs a second, edge-on view to carry it.

### hook — 29 notions

| Cartridge | Notions | Subtypes | Parameters driven |
| :-- | --: | --: | :-- |
| `hook-and-eye` | 14 | 13 | `columns`, `rows`, `size_mm`, `plate_t`, `wire_d` |
| `trouser-hook-bar` | 9 | 9 | `hook_width`, `sew_holes`, `plate_len`, `plate_t`, `wire_d`, `gap` |
| `lacing-hook` | 2 | 2 | `hook_count`, `pitch`, `plate_w`, `cord_dia` |
| `boot-hook-puller` | 1 | 1 | `blade_w`, `blade_t`, `hook_r` |
| `carabiner` | 1 | 1 | `inner_w`, `spine`, `opening` |
| `hook-loop-tape` | 1 | 1 | `overlap_mm` |
| `snap-hook-swivel` | 1 | 1 | `webbing_w`, `webbing_t` |

The second-largest kind, and the one whose leading cartridge is genuinely a
*grid*, not a single part: 15 subtype phrases say "hook-and-eye" (several
spelling the grid out — "hook-and-eye gusset closure (3 cols x 2 rows)",
"hook-and-eye bra back (3 cols x 2 rows)"), 7 say hook-and-bar, and the tail is
lacing hooks (2), swivel snap-hooks (2), a boot hook and a hook-and-loop
closure.

`hook-and-eye` is the only trim in the whole inventory whose glyph is
**tiled rather than scaled**: `columns` (1–6) and `rows` (1–4) are driven by all
14 of its notions, so the glyph is an array whose element is sized by
`size_mm` (4–20 mm) and stroked by `wire_d` (1–4 mm). `trouser-hook-bar` is a
plate glyph — `plate_len` (8–25 mm) × `hook_width` (6–20 mm) with `sew_holes`
(2–8) marks. `lacing-hook` is a repeat along a line: `hook_count` (2–8) at
`pitch` (8–25 mm). `hook-loop-tape` has exactly one driven parameter,
`overlap_mm`, i.e. its glyph is a plain band of the closure's length.

### boning — 5 notions

| Cartridge | Notions | Subtypes | Parameters driven |
| :-- | --: | --: | :-- |
| `boning-stay` | 4 | 4 | `stay_length`, `stay_width`, `channel_clear`, `stay_t`, `channel_wall` |
| `corset-busk` | 1 | 1 | `busk_len`, `plate_w`, `plate_t`, `knobs` |

The smallest kind after rivet, and the most nearly 1D. A stay glyph is a
rectangle: **`stay_length`** (40–400 mm, step 5) × **`stay_width`** (4–15 mm).
The busk adds a repeat: **`busk_len`** (120–500 mm) × `plate_w` (8–40 mm) with
**`knobs`** (2–12) knob/keyhole marks down its length. `channel_clear`,
`channel_wall` and the `_t` params are print-fit and thickness.

### custom — 154 notions

`custom` is the residual kind and behaves like one: 154 notions, 152 distinct
subtype phrases, 70 cartridges. It is not one glyph family and should not be
drawn as one. Its shape:

- **8 notions have no `hardware_ref` at all**, and every one of the eight is a
  garment whose subtype states it is closure-free — `agbada-boubou`,
  `aymara-pollera-skirt`, `chamanto-poncho`, `folk-dirndl-apron`,
  `gho-wrap-robe`, `kente-wrap-cloth`, `salwar-kameez-set`,
  `vyshyvanka-shirt`. These need an *absence* mark in a flats gallery, not a
  trim glyph.
- The head of the distribution is a small set of recognisable trims that simply
  have no dedicated kind: `cord-lock` (9), `bra-ring-slider` (7),
  `hook-loop-tape` (7), `magnetic-clasp` (7), `hat-size-reducer` (5),
  `strap-buckle` (5), `toggle` (5), `tpu-lattice-panel` (5), `bra-underwire` (4),
  `led-channel` (4), `sensor-mount-plate` (4), `tpu-pleat-panel` (4).
- The tail is 58 further cartridges at 1–3 notions each.

Across the whole kind the most-driven parameters are `wall` (19), `cord_dia`
(15), `strap_w` (14), `wire_d` (12), `cords` (11), `cols` (10), `rows` (10),
`strip_length` (10), `webbing` (8), `strip_width` (8), `disc_dia` (7),
`sew_margin` (7) — i.e. the same five classes as the named kinds, plus one that
is unique to this bucket: the **printed-textile panels** (`tpu-*`), which are
tilings driven by `cols`/`rows`/`tile` and are area fills rather than trims.

## The drawing vocabulary the data actually contains

Every one of the 965 resolved `params_map` keys falls into one of five classes.
A glyph spec needs a rule for each, and needs to ignore the fifth.

| Class | Examples from the data | What a glyph does with it |
| :-- | :-- | :-- |
| **Extent** — the drawn size | `zip_length`, `stay_length`, `busk_len`, `plate_len`, `strip_length`, `frame_h`, `bow_depth` | scales the glyph along its long axis |
| **Gauge / section** — the mating dimension | `button_ligne`, `diameter_mm`, `snap_dia`, `inner_dia`, `cap_dia`, `webbing`/`webbing_w`/`strap_w`/`strap_width`, `tape_width`, `stay_width` | scales the glyph across, and is the value the label should show |
| **Count** — discrete repeats | `hole_count`/`holes`, `sew_holes`, `columns`, `rows`, `hook_count`, `knobs`, `cords`, `cols`, `card_count` | sets how many marks are drawn, not how big |
| **Pitch / step** — spacing of repeats | `hole_spacing`, `pitch`, `chain_size`, `coil_dia`, `pleat_pitch` | sets the spacing between those marks |
| **Depth & fit** — invisible face-on | `thickness`, `plate_t`, `disc_t`, `wall`, `web_t`, `wire_d`, `gap`, `snap_clear`, `engage_clear`, `channel_clear`, `washer_t`, `barrel_h`, `cap_h` | excluded from the glyph, except where a stroke weight (`wire_d`, `wall`) is a deliberate stand-in |

Two consequences worth stating before anyone draws:

1. **Three kinds are arrays, not shapes.** `hook-and-eye` (`columns` × `rows`),
   `lacing-hook` (`hook_count` at `pitch`) and the `tpu-*` panels
   (`cols` × `rows`) are driven by counts in every notion that uses them. A
   glyph set built purely on scaling will be wrong for 16+ notions.
2. **One kind is mostly depth.** `rivet`'s most-driven parameter is `cap_h`,
   and `garment-eyelet`'s second is `barrel_h` — both invisible face-on. Those
   two want a paired edge-on mark if the gallery is to distinguish a light
   rivet from a heavy one.
